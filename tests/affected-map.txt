# What tests/affected.sh cannot see by itself: which tests cover a file no QML closure
# reaches (scripts, runners, shell files, fixtures read by a runner), what the lock scenarios
# that are not about the lock screen itself cover, and what needs no test. Read by
# tests/affected.sh; tests/affected-selftest.sh (affected.sh --check) fails on a tracked file
# placed nowhere, on a line here whose pattern matches no file, and on a target that names
# nothing.
#
#   <pattern> <target>…    `*` matches any characters, `/` included; every line that
#                          matches a changed file adds its targets
# Targets:
#   unit:<Suite>  unit:all       unit suites (tests/run-unit.sh)
#   modules:all                  every module fixture part of tests/run-all.sh
#   lock:<scenario glob>  lock:all
#                                lock scenarios (tests/lock/run.sh), besides those a change
#                                in the lock closure runs
#   self:<script>                a self-test or a runner, run as it is
#   mockup:<kind>/<name>  mockup:all
#                                component and view mockups (tests/run-mockups.sh
#                                --by-system); each covers its own folder's closure by
#                                itself, planning mockups are placed with none
#   none                         no test needed (a decision, written down)
# A line whose pattern starts with "+" only adds its targets: it places nothing, so a file
# it matches still needs a closure or a line of its own (`--check`).
# Directives:
#   @lock-roots <pattern>…       the lock closure starts from these: a change in it runs
#                                every scenario but the @not-lock ones
#   @not-lock <scenario glob>…   scenarios that are not about the lock screen: they run
#                                on their own lines only
#   @lazy <file>…                lists of views loaded when shown: followed only from a
#                                suite that names the file itself
